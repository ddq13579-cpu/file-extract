# 文档智能结构化系统 V1 - Codex 开发指令

请从当前目录开始，重新构建一个全新的 Docker 化项目。

项目目标：

用户通过网页拖入一个文件或文件夹，系统自动扫描其中的 PDF 和图片文件；PDF 优先直接提取文字，图片使用本地 PaddleOCR；得到原始文字后，将文字 + 用户定义的提取模板发送给 Google Gemini API；Gemini 严格按照模板返回 JSON；JSON 保存到 SQLite 数据库；最终可以查看结果并导出 Excel。

核心链路：

网页拖入文件/文件夹
→ 文件扫描
→ PDF → PyMuPDF
→ 图片 → PaddleOCR
→ 原始文字
→ Google Gemini API
→ 结构化 JSON
→ SQLite
→ Excel

本项目不是 CRM，也不要加入销售管理、佣金、客户管理等业务功能。

==================================================

Frontend:
- Vue 3
- Vite
- TypeScript

- Axios

生产环境：
- Vue 使用 Vite build
- 构建后的 dist 由 Nginx 提供
- 不使用 Apache

Backend:
- Python
- FastAPI
- SQLAlchemy
- SQLite
- Pydantic

Document:
- PyMuPDF
- Pillow
- PaddleOCR

AI:
- Google Gemini API
- 使用 Google 官方 Python SDK
- API Key 从环境变量读取
- 不要把 API Key 写入代码

Excel:
- openpyxl

Deployment:
- Docker Compose


==================================================
二、最终 Docker 架构
==================================================

必须使用以下运行服务：

1. nginx
2. backend
3. worker

Vue 前端不需要单独运行 Node/Vite 开发服务器。

生产架构：

浏览器
  ↓
Nginx
  ├── Vue 静态文件
  └── /api → FastAPI
                 ↓
              SQLite
                 ↓
              Worker
              ├── PyMuPDF
              ├── PaddleOCR
              └── Gemini API

Nginx 要负责：
- 提供 Vue dist 静态文件
- 将 /api/ 请求反向代理到 backend
- 可以配置上传大小限制
- 为以后 HTTPS 留出配置空间

浏览器上传文件的路径：

浏览器
→ Nginx
→ FastAPI
→ /data/uploads

不要让浏览器直接访问 SQLite、worker 或内部文件路径。

不要让 Nginx 直接负责保存上传文件。

不要使用 Apache。

==================================================
八、PDF处理
==================================================

PDF 默认不做 OCR。

流程：

PDF
→ PyMuPDF
→ 提取所有页面文字
→ 合并文字
→ 保存 ocr_results
→ Gemini
→ JSON
→ records

一个多页 PDF 是一个 document。

例如一个 28 页保险 PDF：

1 个 document
1 条 record

不是 28 条记录。

如果 PDF 没有有效文字，第一版可以：
- 标记为 failed 或需要 OCR
- 明确记录原因
- 不要偷偷把 PDF 当成普通图片处理

后续版本再增加：
扫描 PDF → 页面转图片 → PaddleOCR。


==================================================
九、图片 OCR
==================================================

图片：

JPG / PNG / WEBP / BMP / TIFF / HEIC

统一：

图片
→ PaddleOCR
→ raw_text
→ 保存 ocr_results
→ Gemini
→ JSON

PaddleOCR 必须本地运行。

不要调用第三方 OCR API。

不要把原始图片发送给 Google Gemini 做 OCR。

Google Gemini 在 V1 只负责处理：
- PDF 提取出来的文字
- PaddleOCR 提取出来的文字


==================================================
十、PaddleOCR
==================================================

PaddleOCR 安装在 worker 容器。

V1 使用 CPU。

不需要：
- GPU
- CUDA

要求：
- 中文识别
- OCR 模型尽量只初始化一次
- 不要每处理一张图片就重新加载模型

请根据当前稳定版本正确使用 PaddleOCR API。

如果 PaddleOCR 不同版本 API 有差异，请选择当前可正常运行的稳定版本，不要使用已经废弃的接口。

如果 HEIC 依赖额外系统库，请正确加入 Docker 镜像。

==================================================
十二、Gemini严格结构化输出
==================================================

不要把模板字段写死。

后端根据数据库：

templates
template_fields

动态生成 Gemini 请求。

要求：

1. 只能输出模板定义的字段
2. 不允许增加额外字段
3. 找不到信息时返回 null 或空字符串
4. 不允许编造
5. date → YYYY-MM-DD
6. number → 数字
7. text → 字符串
8. boolean → true/false
9. 严格 JSON
10. 不要 Markdown
11. 不要解释文字

优先使用 Gemini API 的 structured output / JSON Schema 功能。

如果当前 Google 官方 SDK 支持 response schema，请使用 response schema。

Gemini 返回结果必须经过 Pydantic / JSON Schema 验证后才能写入 records。

==================================================

流程：

→ processing

→ ocr_completed
→ ai_processing

→ completed

例如：

002.jpg completed
003.jpg failed
004.pdf completed


==================================================
十五、重复文件
==================================================

不要重新调用 Gemini。

提示：

文件已经处理过。

如果文件内容发生改变：
SHA-256 改变
→ 可以重新处理。

==================================================
二十二、Nginx
==================================================

必须使用 Nginx。

不要使用 Apache。

Nginx：
1. 提供 Vue dist 静态文件
2. /api/ 反向代理到 backend
3. 设置合理的 client_max_body_size
4. 为以后 HTTPS 预留配置

生产环境不要运行 Vite dev server。

Vue：

npm run build
→ dist
→ Nginx

Nginx 示例逻辑：

/       → Vue 静态文件
/api/   → http://backend:8000/api/

Vue Router 如果使用 history 模式，要正确配置 try_files。
